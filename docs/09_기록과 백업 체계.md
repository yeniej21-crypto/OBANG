# 09 · 기록과 백업 체계 (설계안 + 현재 상태)

최종 갱신: 2026-10-04 · 상태: 아래 '지금 실제로 돌아가는 백업'은 동작 중. 예약 브리핑 · 하루 마감 자동화(2장)는 은주가 요청하면 구축(To-do '기록 · 백업 · 업무 자동화 체계 구축').

## 목표

대화 · 결정 · 약속 · 산출물 · 코드가 하나도 빠지지 않고 기록되고, 어느 세션에서든 같은 상태에서 이어 가며, 할 일이 제때 다시 떠오르게 한다.

## 1. 기록하는 곳 여섯 칸 (한 정보는 한 곳에만)

| 칸 | 무엇을 | 어디에 | 언제 갱신 |
| --- | --- | --- | --- |
| 결정 | 정한 것 · 바꾼 것 · 이유 | docs/01 결정 기록(프로젝트 문서와 동기화) | 결정이 나온 그 턴 |
| 할 일 · 약속 | 누가 · 무엇을 · 언제. Claude가 "하겠다"고 한 것도 포함 | Claude Docs 「오방사주 오픈 To-do v2」 | 그 턴 + 하루 마감 |
| 작업 이력 | 코드 변경 · 배포 · 생성 작업 ID · 겪은 문제 | HANDOFF.md, DEPLOYS.log, recipes/history.json | 작업마다 |
| 캐릭터 | 이름 · 역할 · 원본 그림 · 영상 ID · 파일 위치 · 대사 · 상태 | docs/10 캐릭터 시트 | 캐릭터를 만들거나 바꾸거나 확정 · 탈락시킨 그 턴 |
| 산출물 지도 | 모든 문서 · 아티팩트의 이름 · 링크 · 용도 · 최신 여부 | docs/00 시작 안내의 '문서 지도' 표 | 새 문서를 만들 때 |
| 코드 · 자산 | proto · tools · server · bk · work · recipes | GitHub source 브랜치(백업) + main(배포) | 배포마다 자동 |

규칙: 채팅에서만 답하고 끝난 내용(판단 · 분석 · 메시지 초안)도 결정이나 할 일이 생기면 그 턴에 위 칸에 옮긴다. 채팅은 기록이 아니다.

## 2. 리듬 (자동화)

| 언제 | 무엇 | 방식 |
| --- | --- | --- |
| 매 턴 | 결정 · 약속을 01 · To-do에 반영, 코드 바꾸면 백업 | Claude 작업 규칙 |
| 매일 아침(평일) | 오늘 할 일 3~7개 브리핑(To-do 기준, 마감 임박 · 막힌 것 먼저) | 이 세션으로 돌아오는 예약 메시지 |
| 매일 저녁(평일) | 하루 마감: 오늘 대화에서 결정 · 할 일 · 약속 추출 → 01 · To-do · HANDOFF 갱신 → 백업 → 3줄 요약 | 이 세션으로 돌아오는 예약 메시지 |
| 매주 월 | 문서 정합성 점검(날짜 · 숫자 · 옛 문서 표시), 문서 지도 갱신, 프로젝트 문서 내보내기 | 예약 메시지 |
| 매월 | 복구 연습(restore.sh로 다른 폴더에 되살려 열어 보기) | 예약 메시지 |

## 3. 누락 방지 장치

- 약속 목록: Claude가 "하겠다"고 한 일은 To-do에 담당 Claude로 즉시 올린다. 하루 마감 때 미완료 약속을 다시 보고한다.
- 결정 한 줄 규칙: 결정은 날짜 · 무엇 · 이유를 한 줄로. 바뀌면 옛 줄을 지우지 않고 새 줄을 위에.
- 옛 문서 표시: 내용이 바뀐 문서는 맨 위에 '이전 버전 · 최신은 여기' 링크.
- 세션이 끊길 때: 새 세션은 HANDOFF 맨 위 '지금 바로 이어서 하기' → docs/00 → 01 → To-do 순서로 읽고 시작한다.
- 백업 확인: backup.sh가 올린 뒤 원격과 대조, 키처럼 보이는 문자열이 있으면 멈춤(이미 동작).

## 4. 구축 순서 (요청 받으면)

1. docs/00에 '문서 지도' 표와 '새 세션 시작 순서' 추가
2. 오늘까지 채팅에만 있는 결정 · 약속을 01 · To-do로 일괄 옮기기(누락 점검)
3. 평일 아침 브리핑 · 저녁 마감 예약 메시지 설정(시간은 은주와 정함)
4. 주간 점검 · 월간 복구 연습 예약
5. 첫 하루 마감을 같이 돌려 보고 형식 확정

## 지금 실제로 돌아가는 백업 (2026-10-04 기준)

| 무엇 | 어디에 | 언제 |
| --- | --- | --- |
| 화면 원본 proto 전체(밑줄 임시 파일 제외) · 도구 스크립트 · bk(옛 화면 버전) · work(생성 요청 · 가공 스크립트) · server · DEPLOYS.log · HANDOFF.md | GitHub `yeniej21-crypto/OBANG` source 브랜치 | 배포할 때마다 자동(deploy_push.sh 끝에서 backup.sh). 배포 없이 작업만 했을 때는 `bash backup.sh "메모"` |

| 인수인계서 | source 브랜치 HANDOFF.md 하나(작업 폴더의 HANDOFF.md는 링크). 맨 위 '지금 바로 이어서 하기'에 현재 상태 · 남은 일 · 고정 규칙 | 작업 묶음마다 |
| 배포 기록 | DEPLOYS.log(시각 · 커밋 · 한 줄 메모) | 배포마다 자동 |
| 생성 영상 · 그림 | Higgsfield 계정(d8j0 · d2ol7 주소). 쓰는 주소는 화면 코드와 HANDOFF에 적힘 | 생성할 때 |
| 프로젝트 문서 | 이 프로젝트 claude/00~11 | 결정 · 구조가 바뀔 때 |
| 화면 옛 버전 | proto 옆 bk/ 폴더(파일이름.pre_무엇.html) | 화면을 크게 바꾸기 전마다 |

- 새 세션 · 새 환경에서 되살리기: source 브랜치에서 `tools/restore.sh`를 받아 `bash restore.sh` → 작업 폴더에 proto · 도구 · bk · work 복구, HANDOFF 링크 생성. 그다음 HANDOFF 맨 위 → docs/00 → 01 순서로 읽고 시작.
- 되돌리기: 화면 하나는 bk/의 옛 파일을 proto로 복사해 다시 배포, 사이트 전체는 `bash rollback.sh` → 시점 목록 확인 → `bash rollback.sh <배포 커밋>`(기록은 지우지 않고 예전 내용으로 새 커밋).
- 비밀 값(키 · 비밀번호)은 어떤 백업에도 넣지 않는다. 키는 넷리파이 환경변수에만, 비밀번호는 비밀번호 관리자에만.
