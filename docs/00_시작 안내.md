# 00 · 시작 안내 (새 채팅은 이 문서부터)

오방사주는 녹트서울(UDID 자회사 · 독립법인)이 2026년 11월 16일(월) 웹으로 여는 AI 사주 서비스다. 은주가 기획 · 화면 · 비주얼을 맡고 Claude와 직접 개발한다. 결제 연동은 사내 개발팀이 지원한다.

## 새 채팅에서 이어 하는 순서

1. 이 문서 → `01_현황과 결정` → 할 일에 맞는 문서(02~06)를 읽는다.
2. 할 일 목록과 날짜는 Claude Docs 문서 「오방사주 런칭 로드맵 · 개발 협업 가이드」의 '마스터 플랜 · 전체 체크리스트 · 일정표' 탭이 기준이다. 체크리스트 상태를 먼저 확인한다.
3. 코드 작업이면 GitHub `yeniej21-crypto/OBANG`에서 한 번에 복구한다.
   - `source` 브랜치 = 작업 원본 전체: proto(화면) · tools(스크립트) · bk(화면 옛 버전) · work(생성 요청 · 가공 스크립트) · recipes(생성 레시피) · docs · server · HANDOFF.md · DEPLOYS.log
   - `main` 브랜치 = 배포본(넷리파이가 자동 배포)
   - 복구: `git clone -b source https://github.com/yeniej21-crypto/OBANG /home/claude/obang-src && bash /home/claude/obang-src/tools/restore.sh <작업폴더>` → 작업폴더에 proto · 스크립트 · bk가 깔린다.
   - 배포: `bash <작업폴더>/deploy_push.sh "내용"` (검사 → 빌드 → main 배포 → source 자동 백업까지 한 번에)
   - 배포 없이 작업만 했을 때도 `bash <작업폴더>/backup.sh "내용"`을 수시로 돌린다.
   - 배포본 되돌리기: `bash <작업폴더>/rollback.sh`(배포 목록) → `bash rollback.sh <커밋번호>`
4. 작업이 끝나면 `작업 인수인계서 (프로토타입)`에 번호를 이어 기록하고, `01_현황과 결정`의 결정 기록을 갱신한다. 프로젝트 문서도 같은 내용으로 맞춘다.
5. 영상 · 그림을 다시 만들어야 하면 `08_생성 레시피`부터 본다(작업 ID · 시작 그림 · 대사 · 목소리 · 설정, 은주가 사이트에서 직접 만드는 법).

## 꼭 지킬 것

- 답은 항상 한국어로.
- 크레딧을 쓰기 전에 계획(대사 · 컷 수 · 예상 크레딧)을 먼저 보여 주고 승인받는다. 크레딧은 아끼되 품질은 낮추지 않는다.
- API 키는 넷리파이 환경변수에만 둔다. 채팅 · 코드 · 문서에 절대 붙이지 않는다.
- 배포 전에는 `check_js.py`로 스크립트 오류 검사를 반드시 돌린다(2026-10-01 다음 연애 화면 장애 이후 추가).
- 백업은 수시로: 화면 · 문서를 고칠 때마다 배포(자동 백업) 또는 backup.sh. 새 그림 · 영상이 서비스에 들어가면 인수인계서에 작업 ID를 꼭 적는다(레시피 자동 추출의 기준).
- 비밀 정보(키 · 비밀번호 · 계좌 · 카드 · 인감 서류)는 문서 · 백업 어디에도 올리지 않는다. backup.sh가 키처럼 생긴 문자열을 발견하면 멈춘다.
